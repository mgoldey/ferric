# API documentation

The crate-level API docs are generated by `rustdoc` and published alongside this
book.

<div class="warning">

**[Browse the API documentation →](../api/ferric/index.html)**

Generated by `rustdoc` and published alongside this book.

That link is only present when the most recent CI run on `main` succeeded.
`cargo doc` does not link, but it runs build scripts, and
`ferric-integrals`' build script compiles a C++ shim that needs `libint2.hpp`.
The API docs are therefore built by the CI workflow, which already builds and
caches libint2, and handed to the docs workflow as an artifact. If CI was red, the
book still publishes and this link 404s; generate the docs locally in that
case.

</div>

## Generating locally

```bash
cargo doc --workspace --no-deps --open
```

Drop `--no-deps` to include dependency documentation as well (much slower, and
much larger).

If that fails with *"Only one may be documented at once since they output to
the same path"*, add `--exclude ferric-python`. The pyo3 crate's lib is
named `ferric` so that Python's `import ferric` works, and that name collides
with the `ferric` facade crate. Excluding it loses nothing: it is a `cdylib`,
and its surface is documented in
[Python bindings](../using/python.md).

## Entry points

| Crate | Start at |
|---|---|
| `ferric_core` | `Molecule`, `BasisSet`, `Shell` |

| `ferric_mp2` | `ri_mp2`, `oo_ri_mp2` |

| `ferric_dft` | `KsXc`, functional construction via libxc |
| `ferric_tensors` | the `einsum!` macro |

## On reading the docs

Doc comments record design reasoning at the point of use: convergence hazards,
memory-accounting details, parallelizations that would be unsafe, and
optimizations that were rejected, with the reason. They are kept next to the
code rather than in prose docs, so they stay in sync with it.
